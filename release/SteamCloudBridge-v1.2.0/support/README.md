# SteamCloudBridge v1.2.0 · 使用说明

**这是什么**：给《黑暗之魂3》和《黑暗之魂2》搬存档的工具。四件事：
① 让魂三的存档正常上云 / 从云下来；② 把另一台机器上的魂三存档搬到这台机器的正确位置；
③ 只读地查看本机云存档状况；④ 魂二**没有 Steam 云**，改为把存档导出成文件夹，用你自己的网盘或 U 盘跨机搬。

整个包**解压即用**：不用装 Python，不用改 Steam 设置，不联网上传任何东西。

> **魂二和魂三不是一回事。** 魂三支持 Steam 云（所以有"把云通道点亮"这一步）；魂二**根本不支持**云存档——不是设置没开，是这游戏没有这个功能，也没有开关可以点，**而且这一点改不了**（云存档由游戏方决定，第三方加不上）。所以魂二走的是"导出成一个文件夹 → 放进网盘同步目录 / U 盘 → 换台机器导入"。用法与原因见**第六节**。

## 包里有什么

解压后**顶层只有两个文件**——你平时只碰这两个：

| 顶层文件 | 干什么 | 会写盘吗 |
|---|---|---|
| `RUN-GUI.bat` | **平时就双击这个**：打开图形向导，一步步带你走完 | 只在你点"备份/导入"时才写 |
| `SteamCloudBridgeGUI.exe` | 向导本体。上面的启动器会自动找到它，不用你管 | ❌ 不改存档 |
| `support\` | **其余全部文件都收在这个文件夹里**，平时不用打开 | —— |

`support\` 里面（命令行 / 查问题时才用）：

| 文件 | 干什么 | 会写盘吗 |
|---|---|---|
| `RUN-SYNC.bat` | 命令行版日常入口（不开窗口，直接敲命令的那种） | ❌ 不会 |
| `RUN-BRIDGE.bat` | 把一份 `.sl2` 存档搬到正确位置（可选顺带推上云） | ✅ 会（须输 `YES`） |
| `RUN-PROBE.bat` | 只读体检：看清本机云存档状况，报告生成在**你自己的电脑上** | ❌ 不会 |
| `RUN-PROBE-TARGET.bat` | 专项扫描：只查魂三 `374320` / 法环 `1245620` | ❌ 不会 |
| `RUN-CROSS-VERIFY.bat` | 两台机器之间核对该游戏存档是否**逐字节一致**（不启动游戏） | ✅ 会（从云下发一个文件） |
| `RUN-CLOUD-BAIT.bat` | 云接受性验证（诱饵法，需要本机有 Python 3） | ✅ 会（只新增再删一个诱饵文件） |
| `*.exe` / `*.py` | 上面脚本调用的本体。`.exe` 免装 Python；`.py` 是可读源码版，功能一样（需要机器上装了 Python；图形版还需要 tkinter） | —— |
| `README.md` | 全部说明就这一份（就是你正在看的这个文件） | —— |

> **只需要记住 `RUN-GUI.bat` 一个。** 其余的都是命令行/查问题用的，平时不用管。
> 所有工具都**只搬字节、不修改存档内容、不注入、不改游戏文件**。

> 为什么把东西收进 `support\`：以前十几个文件平铺在一个文件夹里，拿到手第一件事就是"我该双击哪个"。现在顶层只有**启动器 + 向导本体**，双击哪个不需要再想。命令行脚本仍然能用——它们和各自的 `.exe` 待在同一个文件夹里，所以内部路径不用你操心。

## 一、图形向导：双击 `RUN-GUI.bat`

打开后左边五步，跟着点就行，不用记任何命令。

| 步骤 | 它做什么 |
|---|---|
| **1 检查环境** | 自动看清：Steam 装在哪、游戏装没装、存档在哪、云端有没有副本、云通道亮没亮。**只看不改。** |
| **2 备份存档** | 一键把整个存档目录复制一份到程序旁边，复制完逐个文件核对校验值。出问题可以还原。 |
| **3 每次玩之前** | 三步：① 点按钮帮你打开 Steam 控制台 → ② 把窗口里那一行**复制粘贴**进去 → ③ 窗口自己确认成功，然后点"启动游戏"。 |
| **4 遇到问题** | 常见故障怎么处理，以及"打开存档文件夹 / 打开备份文件夹"的快捷按钮。 |
| **5 魂2 存档** | 魂二没有云，所以这一页**不点亮任何东西**：把存档"导出到文件夹"，换台机器再"从文件夹导入"。详见第六节。 |

**窗口会自己等你**：你没敲之前它显示"● 未开始"，敲进去之后几秒内变成"✓ 已点亮"。

> 界面上写"没有成功提示是正常的"—— 这是真的。Steam 控制台对这类命令**不打印成功信息**，只有回显一行赋值。所以向导是靠**读 Steam 自己的日志**来判断你到底敲没敲进去，而不是靠屏幕上有没有字。

**打不开向导？** 那就用命令行版 `RUN-SYNC.bat`（见第二节），功能一样。

## 二、命令行版：每次玩之前，双击一次 `RUN-SYNC.bat`

> 这一节的脚本都在 **`support\`** 文件夹里（第二节往下都是"进阶/查问题"用的，日常不需要）。

1. **双击 `support\RUN-SYNC.bat`**（它会先检查：游戏没在跑、Steam 在运行）。
2. **照屏幕提示敲一行**（怎么敲见第三节）：
   ```
   testappcloudpaths 374320
   ```
3. 看到 `[OK] the cloud channel is ON ...` 就成了 → **游戏自动启动** → 正常玩 → **退出游戏时 Steam 自己把存档同步上云**。

只想点亮、不想让它自动启动游戏：
```bat
RUN-SYNC.bat daily --appid 374320 --manual
```

**为什么必须每次双击？**
Steam 的云开关有**两层**：①账号级（写过就记住）；②**游戏级** —— 魂三这一层只在当前 Steam 会话有效，**重启 Steam 就失效**，本地没有任何配置文件可以写入。所以"装一次永远生效"技术上做不到。代价只是每次 10 秒，而且点亮是**幂等**的（重复点没有副作用）。

⚠ **点亮之后不要重启 Steam** —— 本次点亮会作废，重新双击一次即可。

## 三、要敲的那两行

**先打开 Steam 控制台**（Steam 必须正在运行）：
按 **`Win + R`** → 粘贴 `steam://open/console` → 回车。Steam 会多出一个 **Console（控制台）** 标签页。
（没反应就试：浏览器地址栏粘同一串；或给 Steam 快捷方式"目标"末尾加 ` -console` 重启 Steam。）

> ⚠ 控制台**打开了 ≠ 输入行有焦点**。打字之前，先用鼠标**点一下最底下那一行输入框**。

**第一行** —— 打开这个游戏的云通道：
```
testappcloudpaths 374320
```

**第二行** —— 让 Steam 从云端拉一次：
```
cloud_sync_down 374320
```

要点：
- **顺序不能反**：必须先 `testappcloudpaths`（开通道），再 `cloud_sync_down`（下载）。反了 Steam 会拒绝，日志里写 `AutoCloud is disabled`。
- **没有"成功"提示是正常的** —— 成功只会回显一行赋值。
- 想自检：敲 `find testappcloudpaths`，值是 `"374320"` 就是开着；`"0"` = 没生效，把第一行再敲一遍。
- **敲错没有任何破坏性后果**，重新敲正确的就行。这两行是 **Steam 自带的云存档调试命令**（出自 Valve 官方 Steamworks 文档），不是外挂、不是破解、不改任何游戏文件。

## 四、把一份存档搬到这台机器

**什么时候用**：你在**另一台机器**上有魂三存档，Steam 云没帮你同步过来；或你手工备份了 `DS30000.sl2`，现在想放回去。
**什么时候别用**：改存档内容（它不是修改器，只做整文件搬运）；搬**别人的**存档（会被直接拒绝）。

**用法**：完全退出 Steam → 双击 `RUN-BRIDGE.bat` → 按提示回答 5 个问题。
- `2)` 的存档文件路径**可以直接把文件拖进窗口**，不用手打。
- `4)` **只有这里输入 `YES` 才会写盘**，其他任何输入都等于取消。
- `5)` 回车 = 写完顺带推上云（会自己启动 Steam）。
- 第 4 步之前的一切都是**只读**的。

**三条硬规矩**（工具强制，无法绕过）：
1. **只搬你自己账号的档** —— 读存档目录里记录的 `accountid` 与当前登录账号比对，不一致直接拒绝。
2. **必须完全退出 Steam** —— 检测到 Steam 在跑直接拒绝。
3. **不写没有退路的覆盖** —— 写前强制备份 + 拍快照，写坏了能退回去。

**后悔药**（默认只打印将做什么，加 `--yes` 才真写）：
```bat
RUN-BRIDGE.bat rollback --snapshot "backup\DS30000.sl2.snapshot.json"
RUN-BRIDGE.bat rollback --snapshot "backup\DS30000.sl2.snapshot.json" --yes
```
也可以什么都不用工具：把 `backup\DS30000.sl2` 手动拷回存档目录即可（存档目录在诊断那一步会打印出来）。

## 五、想看清楚本机云存档状况

双击 **`RUN-PROBE.bat`** → 几秒后自动打开 `reports` 文件夹，报告都在**你自己这台机器上**：

| 文件 | 是什么 |
|---|---|
| `machine_profile.md` | 人能读的摘要 |
| `machine_profile.share.json` | 脱敏后的结构化数据 |
| `machine_profile.appids.txt` | 有云存档痕迹的游戏列表 |
| `private\machine_profile.json` | 完整档，**含账号 ID 与绝对路径** —— 别外发 |

它**全程只读**：只读文件名、大小、修改时间，不读存档内容，不写任何东西，不联网。

（图形向导第一步已经做了同样的事，只是范围更聚焦。）

## 六、魂二：它没有云，用文件夹搬

### 先说清楚为什么不一样

**《黑暗之魂2》不支持 Steam 云存档。** 不是"你的设置没开"，是这游戏**本身**就没有这个功能——所以既没有 `steam_autocloud.vdf`，也没有云端副本，更**没有云通道可以"点亮"**（第三节那两行命令对魂二没有任何意义）。

这不是猜的，四条本机证据都对得上：账号配置 `localconfig.vdf` 里没有这个游戏的云记录；`userdata\<账号>\335300\` 目录**不存在**（从没同步过）；存档目录里没有 `steam_autocloud.vdf`；云日志里它只有一句 `Not running AutoCloud. No config data found`。Steam 商店页也没标它支持云存档。

**那能不能替它加上？** 不能。云存档是游戏方接进 Steam 的功能，属于开发/发行方的事；第三方替它加不上，本工具也不去改游戏、不注入。**所以"魂二也走 Steam 云"这条路就是不通，请不要再在"点亮云通道"那一页折腾它** —— 那里对它永远不会有反应。

能做的就是换一条**你自己控制的传输通道**：把存档打包进一个文件夹，让这个文件夹跨机器可及。以下是本工具对魂二的**最终方案**。

### 两种通道，选一种就行

| 通道 | 怎么做 |
|---|---|
| **网盘同步目录** | 导出的目标文件夹选成 OneDrive / 坚果云 / Syncthing 之类**会自动同步**的目录。另一台机器上打开同一个文件夹直接导入。 |
| **U 盘 / 移动硬盘** | 导出目录直接选 U 盘。插到另一台机器上，用"从文件夹导入"。 |

两者对工具来说是一样的：导出到哪儿、从哪儿导入，都是你当场选的文件夹。

### 怎么用（图形向导第 5 步）

1. 打开向导 → 左侧点 **「5 魂2 存档」**。页面会显示：本机魂二存档在哪、属于哪个账号、几个文件、共多大。
2. 点 **「导出到文件夹…」** → 选一个目录（网盘同步目录或 U 盘）→ 等它算完校验值。
   - 导出目录里会出现 `savepack.json`（清单，含每个文件的 sha256）、`files\`（存档本体）、以及一份 `先读我.txt`。
3. 到**另一台机器**上，同样打开第 5 步 → 点 **「从文件夹导入…」** → 选同一个文件夹 → 确认。
   - 导入前它会**先把那台机器上的现有存档整体备份一份**，然后逐字节写入并复校。
   - 那台机器**从没玩过魂二**也没关系：工具会按你的 Steam 账号把目标目录算出来、自动建好。

### 命令行版（同样的两件事）

```bat
RUN-BRIDGE.bat save-status                       :: 看存档在哪（只读）
RUN-BRIDGE.bat save-out --to "D:\OneDrive\魂二存档"   :: 导出成一个包
RUN-BRIDGE.bat save-in  --from "D:\OneDrive\魂二存档" --yes   :: 导入回来（写盘）
```

想先看它会做什么、先不写盘，把 `--yes` 换成 `--dry-run`。

### 三条同样适用的硬规矩

1. **同一个 Steam 账号才能互相导** —— 包清单里记着导出时的 `accountid`，与目标机器的账号不一致就**直接拒绝**（不给你"选错了还能继续"的机会）。
2. **导入时游戏必须完全退出** —— 检测到魂二在运行就不写（`DarkSoulsII.exe`）。
3. **写入前强制备份** —— 备份失败就中止，一个字都不写；写入用"写临时文件再原子替换"，不会留下写了一半的存档。

### 两个容易误解的点

- **`.co2` 是什么**：如果你装了联机 mod（Seamless Coop），它自己的存档是 `.co2`。默认**一起导出**——因为很多人的最新进度其实在 `.co2` 里，而不是 `.sl2`。两者都带上最保险。
- **这不是"云"**：工具不会上传任何东西。字节只在你选的那个文件夹里出现——同步与否取决于你的网盘客户端，跟这个工具无关。

## 七、会不会被封号 —— 正面回答

- **Steam / VAC：不适用。**《黑暗之魂3》**不使用 VAC**。那两行是 Valve 自己文档里的调试命令；Steam 封号的事由是盗号、欺诈、市场操纵、退款滥用，跟"敲一行客户端自带命令"无关。
- **魂三 softban：对不上。** 触发条件是 **FromSoftware 每周扫描你上传到服务器的存档"内容"里有没有非法数据**（不可能的道具/数值、跳进度等）。本工具**只做字节搬运、不修改内容、拒绝跨账号、不注入、不改游戏文件**。
- **魂二同理**：这条通道完全绕开游戏服务器，工具只在你自己的两个文件夹之间拷字节，游戏根本不知道。
- **唯一红线**：别拿它去搬**别人的**存档 —— 那属于"使用他人存档"，风险来自存档内容，跟用不用云无关。

**工具边界**：`RUN-PROBE.bat` / 向导第 1 步纯只读；写盘只发生在你明确点"备份/导入"或 `RUN-BRIDGE.bat` 里输入 `YES`/加 `--yes` 之后，且写前备份、可回滚。

## 八、出问题怎么办

| 现象 | 处理 |
|---|---|
| 窗口一闪就没了 | 说明中途报错。在文件夹地址栏输入 `cmd` 回车，再输入脚本名回车，看屏幕上的报错 |
| 蓝色"Windows 已保护你的电脑" | 点「更多信息」→「仍要运行」。没买代码签名证书所致，不是病毒 |
| 杀毒软件报警 | exe 会读写 Steam 目录，可能被启发式误报。**不放心就用同目录的 `.py` 版本**，源码可读、输出一模一样 |
| 向导窗口打不开 | 用命令行版 `support\RUN-SYNC.bat`，功能一样。或确认 `RUN-GUI.bat` 和 `SteamCloudBridgeGUI.exe` 在**同一层**（别把启动器单独拖出来） |
| 提示找不到 `.exe` | 别把文件从包里拆散：`RUN-GUI.bat` 要与 `SteamCloudBridgeGUI.exe` 同层，`support\` 里的脚本也要和 `support\` 里的 `.exe` 待在一起 |
| `未发现 Steam` | Steam 装在非默认盘时，检查 Steam 安装目录是否可读 |
| 向导里"状态一直显示未点亮" | 点亮只在**本次开启 Steam 期间**有效。重启过 Steam 就要重新敲一次；敲了还不变，先用鼠标点一下控制台底部输入行再敲 |
| 中途重启过 Steam | 本次点亮作废，重新双击一次 |
| 搬运计划被拦下 | 按提示原因处理：跨账号 → 用你自己账号的档；Steam 在跑 → 完全退出；找不到落点 → 先让游戏跑一次云同步 |
| 想核对两台机器上的存档是否一致 | 双击 `RUN-CROSS-VERIFY.bat`，照提示敲第三节那两行，**全程不要启动游戏** |
| 第 5 步显示"没找到魂二存档目录" | 这台机器还没玩过魂二，正常。**仍然可以"从文件夹导入"**——工具会按你的账号自动把目录建好 |
| 导入时提示"包不完整或已损坏" | `savepack.json` 与 `files\` 里的字节对不上（同步没传完、被网盘改过、或拷了一半）。让网盘同步完成 / 重新拷一次再导 |
| 导入被拒"跨账号" | 那个包是**另一个 Steam 账号**导出的。换用你这个账号自己的包（工具不会让你越过这条线） |
| 导入了但游戏里看不到进度 | 先确认导入时**游戏是退出的**；魂二认的是 `DS2SOFS0000.sl2`，`save-in` 结束时会打印写了哪几个文件——对不上的话把那份 `先读我.txt` 和屏幕输出留好 |
| 想退回导入前的存档 | 导入时屏幕/窗口会打印备份目录（默认在存档目录旁边的 `save-backup\<时间戳>\`），整个拷回去即可 |
